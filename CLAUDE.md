# CLAUDE.md — Promptware Kill-Chain Archive

Operating manual for updating the incident table on this site. Follow it exactly.

## What this is

An archival, defensible extension of **Table II** of the paper *"SoK: The Promptware
Kill Chain"* (NDSS'27). Each incident is one YAML file, coded across a seven-stage
kill chain per the paper's **Section 5 Analysis Protocol**. A static build turns the
YAML into `docs/` (GitHub Pages, served from `docs/` on push to `main`).

## Repo layout

```
data/incidents/<slug>.yml   # SOURCE OF TRUTH — one incident per file
schema/incident.schema.json # JSON Schema every incident is validated against
scripts/validate.mjs        # npm run validate — schema + duplicate-slug + snapshot check
scripts/build.mjs           # npm run build — writes docs/ (index.html, incidents.json, per-incident pages)
scripts/reindex.mjs         # npm run reindex — recompute all ids as YYYY-NNN (run after add/remove)
scripts/add.mjs             # npm run add -- <url> — scaffold a new incident (archives source, assigns next id)
scripts/lib.mjs             # shared helpers (loadIncidents, coverage, dateDisplay, ...)
assets/style.css, table.js  # front-end (copied into docs/ by build). table.js renders incidents.json
docs/                       # BUILD OUTPUT — never hand-edit; always regenerate
```

Never hand-edit anything in `docs/` — it is regenerated by `build.mjs`. Edit `data/incidents/*.yml`
(and `assets/*`, `scripts/*`, `schema/*`) and rebuild.

## Incident schema (fields)

Required: `slug`, `title`, `authors`, `date`, `category`, `target`, `source`, `stages`.
Optional: `id`, `new` (bool → NEW tag), `questioned` (bool → `?` tag).

```yaml
slug: my-incident                 # ^[a-z0-9-]+$ , unique, == filename, == URL path
id: 2025-012                      # ^[0-9]{4}-[0-9]{3}$ ; assigned by reindex.mjs, do not hand-pick
title: "Human-readable title"
authors: "First Last, First Last" # researcher(s)/byline; non-empty
new: true                         # optional
questioned: true                  # optional — set when there is no APPROVED source (see Sources)
date: 2025-08                     # ^[0-9]{4}-[0-9]{2}$  (YYYY-MM). Drives display order.
category: Coding Assist.          # enum, see below
target: "Product / app targeted"  # the real commercial app under attack
source:
  url: "https://..."              # primary source URL (non-empty). "TODO-verify" = NOT sourced yet.
  venue: "Embrace The Red (blog)" # human venue label (nullable)
  type: blog                      # enum: paper | blog | advisory | cve | tweet | other
  snapshot: null                  # local archive filename, if archived (see add.mjs); else null
  archived_at: null
  sha256: null
stages:                           # ALL 7 keys required; each is either null or an object
  initial_access:      {value, justification, evidence: {quote, locator}}
  privilege_escalation: null      # null = stage not present (not counted in coverage)
  reconnaissance:      null
  persistence:         null
  command_control:     null
  lateral_movement:    null
  action_on_objective: {value, justification, evidence: {quote, locator}}
```

`category` enum: `Browser/Search`, `Enterprise`, `Coding Assist.`, `AI Agent`,
`Agentic/CUA`, `Crypto/DeFi`, `AI Worm`, `Multimodal`.

Every non-null stage needs `value`, a one-sentence `justification`, and `evidence`
with a **real quote from the source** plus a `locator` (where in the source). Do not
invent quotes — read the source and quote it.

`coverage` (the Cov. badge) is computed at build time = count of non-null stages.

## Section 5 Analysis Protocol — the coded stage `value`s

Use these exact coded values. A stage that isn't demonstrated is `null` (not counted).

| Stage | Allowed `value` (else `null`) |
|---|---|
| initial_access | `Direct (D)` — attacker prompts the LLM directly · `Indirect (I)` — payload in external content the LLM processes for an unsuspecting user |
| privilege_escalation | `Instruction override (IR)` · `Social eng. (SE)` (role-play / DAN) · `Misc.` (other technique: config abuse, optimized adversarial trigger, find-exec bypass, …) · `null` = no jailbreak needed |
| reconnaissance | `Yes` when the **payload itself** probes user/env/tools to enable later stages · else `null` |
| persistence | `Independent (memory)` — payload told the LLM to store in its memory · `Dependent (channel)` — payload lives in email/calendar/doc/workspace/config retrieved in future interactions · `null` = none |
| command_control | `Promptware-native (●)` — the **LLM itself** re-fetches attacker instructions from a remote server across sessions · `null` = none |
| lateral_movement | `Cross-app (xA)` — a *different* app on the same device is abused · `Cross-device (xD)` — spreads to other devices/clients · `null` = on-app only (OA), incl. cross-agent/plugin **within one app** |
| action_on_objective | one of: `Misinformation` · `Data exfiltration` · `Harmful content` · `Safety (physical)` · `Financial` · `RCE` · `Misc (...)` (e.g. `Misc (DoS)`, `Misc (XSS ATO)`) |

### Hard-won classification rules (apply consistently)

- **C2 is almost never present.** Only counts if the LLM *itself* is the C2 loop
  (e.g. ChatGPT re-reading GitHub-issue commands each session). **RCE that then drops
  a conventional implant (Sliver, botnet, reverse shell) is `command_control: null`**
  — the malware does C2, not the LLM. This excludes every "ZombAI-via-RCE" post.
- **IR vs null priv-esc:** indirect injection that issues overriding instructions to
  perform actions = `IR`. Pure capability abuse with no guardrail override (e.g. the
  app just executes injected code) = `null` (no jailbreak).
- **Reconnaissance is the payload probing** for later stages — NOT "read the secret
  then exfil it" (that's the action) and NOT the researcher's own recon.
- **Lateral movement:** cross-agent / plugin-to-plugin / connector-to-connector
  **within one app** = on-app = `null`. Exfil *to* another service (Slack, a server)
  is a data sink, not lateral movement. `xA` = a genuinely different app on the device
  is driven; `xD` = reaches other machines (worms).
- **Invisible / Unicode-tag injections** are still `Indirect (I)` — the "invisible"
  part is a delivery/evasion trick, not a separate stage.
- **"Independent" persistence = memory implants**; **"Dependent" = a retrieval channel**
  (workspace doc/email/calendar, or a config file like `settings.json`/`.vscode` that
  re-arms each session).

## Scope — what belongs (and what does NOT)

Include only incidents that are **(a) promptware / prompt-injection** AND **(b) demonstrated
against a real commercial LLM-integrated / agentic application** (not a toy demo, not a
bare foundational model). When in doubt, flag it and ask.

Out of scope (drop or ask), based on precedents set this project:
- Access-control / IDOR bugs with no injection (e.g. "M365 Copilot images without auth").
- Data-governance / RAG-permissions talks with no attacker payload (e.g. "RAG-NAROK").
- Supply-chain / deserialization (malicious pickle model files) — no prompt injection.
- Hardware / network / IoT device takeover — no prompt injection (e.g. robot RF/MQTT hacking).
- Malicious custom GPTs / attacker-authored assistants (the whole app is the attacker) —
  not injection into a victim's trusted app (e.g. "Thief GPT" was removed for this).
- Pure jailbreak-technique or measurement-study papers with no production-app incident
  (e.g. "Beyond Jailbreak" measurement study; ArtPrompt/APwT were removed).
- Foundational-LLM-only results (whitebox open-source model internals) unless they also
  demo on a real agent — flag as borderline.

## Sources — approved vs `?`

Approved source venues (in the paper's inclusion policy): peer-reviewed papers (arXiv,
NDSS, CCS, ESORICS, S&P, USENIX), reputable security-research blogs (Embrace The Red /
Rehberger, Zenity, Trail of Bits), recorded conference talks (Black Hat, DEF CON, RSA,
CCC/media.ccc), and documented real-world incidents (AI Incident Database).

- Every incident **must** cite a primary approved source in `source.url`.
- If an incident has **no approved source** (still `TODO-verify`, or a non-approved /
  secondary source), set `questioned: true` so it renders the `?` tag. Un-flag it only
  once a real approved source is attached and the analysis re-derived from that source.
- **Read the actual source before coding.** Do not code from memory or from the title.
  - PDFs (Black Hat / RSA slide decks, arXiv): download and extract text with `pypdf`
    (`python3 -m pip install --break-system-packages pypdf yt-dlp` if needed). WebFetch
    often returns binary for PDFs — use pypdf.
  - YouTube talks: `python3 -m yt_dlp --write-auto-sub --sub-lang "en.*" --skip-download`
    to pull the transcript, then parse the `.vtt`. media.ccc often has NO subtitle track.
  - Web/blog: WebFetch is fine. When a small-model fetch summary is used, treat it as raw
    material and re-apply the protocol yourself — those summaries systematically
    over-attribute C2 / recon / lateral movement.

## ID scheme

`id = YYYY-NNN`: YYYY = the **incident's date year**; NNN = a zero-padded per-year
sequence. Cite `id` in the paper; use `slug` for URLs. IDs carry **no ordering meaning**
— the table sorts by `date`. `add.mjs` assigns the next free id for the year; `reindex.mjs`
recomputes all ids (contiguous per year) after any add/remove. Pre-publication we renumber
freely; there is no `paper_ref` field (removed — it was unused).

## Workflow — adding or changing incidents

1. **Find & read the source** (see Sources). Verify it's in scope. If not, flag/ask.
2. **Write/edit** `data/incidents/<slug>.yml` with coded stage values + real evidence quotes.
   - New incident: create the file (via `add.mjs` to also archive a snapshot, or by hand).
   - Recode existing: overwrite its `stages` (and fill `source.url` if it was `TODO-verify`).
   - Remove: delete the `.yml` **and** its `docs/incident/<slug>.html`.
3. **Reindex:** `npm run reindex` (after any add/remove; skip for pure in-place edits).
4. **Validate:** `npm run validate` — must print `✓ N incident(s) valid`. Fix errors.
5. **Build:** `npm run build` — regenerates `docs/`.
6. **Verify** (optional, for front-end changes): serve and eyeball —
   `npm run serve` then open the table; check the new/changed rows.
7. **Commit & push** to `main`. GitHub Pages redeploys from `docs/` (~1–2 min).
   Commit both `data/` and the regenerated `docs/`.

Batch tip: for many incidents, write a throwaway `scripts/_batch.mjs` that builds the
YAML objects with `js-yaml` `.dump({lineWidth:-1, quotingType:'"'})`, run it, delete it,
then reindex/validate/build.

## Conventions & gotchas

- Schema enums for `persistence` / `command_control` / `lateral_movement` `value` were
  relaxed to free strings during the migration to coded values. If you re-tighten them,
  use the exact coded strings in the protocol table above.
- The `?` (`questioned`) tag currently carries two meanings in the UI tooltip
  ("not demonstrated on a real app") but is also used for "no approved source." If asked
  to distinguish them, split the tag/tooltip.
- Deployment: repo is `github.com/eladfeld/kill-chain-site`; Pages serves `docs/` on `main`.
- Local preview server config lives in `.claude/launch.json` (http-server on `docs/`).
